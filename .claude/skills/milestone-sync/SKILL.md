# 里程碑同步

根据 CLAUDE.md 第五节"IP 资产同步铁律"的规定，在里程碑节点自动列出改动文件清单，生成回拉提醒。本地仓库是唯一可信版本，线上（低代码平台）是部署副本。

## 触发时机

以下里程碑节点必须主动触发同步提醒：

1. **一个功能/bug 修复完成并线上验证通过** — 如"过渡页多主题方案上线、死循环修复确认"
2. **一次对话结束前** — 把当天所有改动文件统一列出，生成带日期的快照提醒
3. **重大版本上线前** — 如"TG001 真人试跑前"、"V19.1 发布前"
4. **Claude 产出完整新文件时** — 立即提醒存本地（用 Write 工具直接写入的文件视为已存，但仍需提醒用户确认线上版本一致）
5. 用户说"/里程碑同步"、"/同步"、"帮我列一下要回拉的文件"

## 同步原则

- **不用每次小改动都回拉** — 打断工作流，效率低。小改动积累到里程碑节点一起处理。
- **本地仓库是 Canonical，线上是副本** — 低代码平台是部署平台，不是代码仓库。所有修改最终必须回到本地。
- **Claude 产出必须双存** — 代码/补丁立即写入本地；修复方案存为 `.patch.md` 记录。不能只留在对话里。

## 执行流程

### Step 1：盘点本次改动

回顾本次会话/本次任务中所有涉及的文件变更：
- 使用 Write/Edit 工具写入或修改了哪些文件？
- 用户在低代码平台编辑器里修改了哪些文件？（通过对话上下文判断）
- 新增/修改了哪些类型的文件？

重点关注的触发场景（来自 ip-sync-rules Rule 4）：
- 修改了任何 .tsx/.ts/.html 文件
- 修改了 AI 插件的 System Prompt
- 新增/修改了场景卡 JSON 数据
- 修改了数据库 Schema 或种子数据
- 新增了路由或页面
- 修复了任何 bug

### Step 2：按存储位置分类

将改动文件分为两类：

**A. 已存本地（Claude 直接写入的）**
- 路径、文件大小、写入时间
- 状态：✅ 已在本地仓库

**B. 仅在线上（低代码平台编辑器修改的）**
- 文件名、修改类型、影响范围
- 状态：⚠️ 需从低代码平台编辑器复制回本地

### Step 3：输出同步提醒

使用 CLAUDE.md 第五节规定的固定格式：

```markdown
---

## 📦 里程碑同步提醒

> 同步时间：[YYYY-MM-DD]
> 里程碑类型：[功能上线 / 对话结束 / 版本发布 / 新文件产出]
> 本地仓库路径：`低代码平台部署_TG001/线上版_YYYYMMDD/`

### 本次改动文件清单

#### ✅ 已存本地（无需操作）

| 文件 | 操作 | 大小 | 时间 |
|------|------|------|------|
| `path/to/file1.tsx` | 新建 | X KB | HH:MM |
| `path/to/file2.html` | 修改 | X KB | HH:MM |

#### ⚠️ 需从低代码平台回拉

| 文件 | 修改类型 | 影响范围 |
|------|----------|----------|
| `path/to/file3.tsx` | 修改 AI 调用代码 | 对话引擎行为 |
| `path/to/file4.json` | 新增场景卡数据 | 新场景可用 |

### 回拉操作指引
1. 打开低代码平台编辑器，找到上述 ⚠️ 文件
2. 复制全部内容
3. 粘贴到本地仓库对应路径，覆盖原文件
4. 文件名建议加日期后缀：`文件名_YYYYMMDD.tsx`
5. 确认本地文件时间戳更新后，本次同步完成

### 历史提醒
- 上次对账发现分叉数：5（2026-07-16）
- 教训：长期未同步导致线上/本地不一致，修复成本高
```

### Step 4：特殊情况处理

**如果本次无线上改动（全部由 Claude 写入本地）：**
```markdown
---

## 📦 里程碑同步提醒

> 同步时间：[YYYY-MM-DD]
> 里程碑类型：[对话结束]

### 本次改动文件清单

所有改动已由 Claude 直接写入本地仓库，本次无需从低代码平台回拉。

| 文件 | 操作 |
|------|------|
| `path/to/file1.tsx` | 新建 |
| `path/to/file2.html` | 修改 |

✅ 本地仓库已是最新版本。
```

**如果用户要求立即同步（非里程碑节点）：**
提醒用户："当前不是里程碑节点。小改动积累到里程碑再统一回拉更高效。如果确实需要立即同步，请确认。"

## 同步后确认

同步提醒输出后，如果用户执行了回拉操作，询问并记录：
- 回拉了哪些文件？
- 是否有文件在线上有更新但本地已过时？
- 是否需要做轻量对账（检查线上文件修改时间 vs 本地文件时间）？

## 与定时任务的衔接

每周一上午的定时任务（CLAUDE.md 第四节）应包括：
- 检查是否有未同步的线上改动
- 更新 V19 方法论复盘
- 检查 memory 是否需要更新

执行定时任务时，本 skill 也应被触发，生成一周的同步汇总。
