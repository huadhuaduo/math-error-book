# 对标检查

在进入任何新任务域或新功能开发之前，强制搜索并分析国际一流做法（Mursion、BetterUp、Abilitie、北森），输出结构化对标报告。这是 CLAUDE.md 一.1 规则的自动化执行。

## 触发时机

以下情况必须触发对标检查：
- 用户说"/对标检查"、"/对标"、"先对标一下"
- 任何新任务域/新功能/新技术方案动手之前
- 用户提出"我们做一个XX功能"但未提及竞品做法时 — 主动提议对标
- 场景设计、架构决策、方法论应用等关键决策前

**历史教训**：同样的错误犯过两次 — 绩效面谈线和团队激励线都跳过了对标，导致走了大量弯路。对标不是为了抄，是为了避免"不知道别人已经踩过的坑"。

## 对标四家标杆

### 1. Mursion（VR 领导力模拟）
**核心特征**：Character Bible 驱动 NPC、Human-in-the-loop 真人操控、VR 沉浸式面谈
**对标维度**：角色一致性、模拟保真度、人机分工、纠错机制
**搜索关键词**：`Mursion leadership simulation character bible human-in-the-loop VR training`

### 2. BetterUp（AI Coaching 平台）
**核心特征**：AI Coach + Content Studio 分离架构、个性化发展计划、行为改变追踪
**对标维度**：AI Coach 深度、内容与引擎解耦、个性化、效果度量
**搜索关键词**：`BetterUp AI coaching platform content studio architecture personalized coaching behavioral change`

### 3. Abilitie（管理模拟 + 双师）
**核心特征**：模拟引导（facilitator）、双师模式（AI + 真人引导）、群体对比学习
**对标维度**：引导设计、双师分工、群体学习、游戏化
**搜索关键词**：`Abilitie management simulation facilitator-led blended learning competitive simulations`

### 4. 北森（中国人才管理 SaaS）
**核心特征**：胜任力模型、行为锚点评分、行业常模数据、360 评估
**对标维度**：行为锚点、胜任力覆盖、常模参照、评估科学性
**搜索关键词**：`北森 人才管理 胜任力模型 行为锚点 评估`

## 执行流程

### Step 1：确认任务域
首先与用户确认当前待启动的任务属于哪个域：
- 场景设计（新的面谈场景/新的 NPC 角色）
- 对话引擎（NPC 行为逻辑、轻声提醒、跑偏检测）
- 反馈系统（评分算法、雷达图、行动承诺）
- 数据追踪（跨场景对比、进步可视化、行为指纹）
- 学员体验（准备页、过渡页、结束页的信息架构）
- 内容管理（场景卡编辑、行为锚点库、原则映射）
- 技术架构（API 设计、状态管理、部署策略）

### Step 2：搜索国际做法
对四家标杆逐一搜索该任务域的做法。使用 WebSearch 工具，每家至少 1 次搜索。

搜索策略：
- 先用中文搜索北森（中文资料更准确）
- 再用英文搜索 Mursion、BetterUp、Abilitie（英文资料更丰富）
- 如果搜索结果不够具体，加搜行业报告、用户评测、技术博客

## 对标原则

1. **对标不是为了抄** — 是为了了解行业基线、避免重复踩坑、找到差异化空间
2. **信息源要可追溯** — 每条发现必须附带搜索来源 URL
3. **差异必须显式呈现** — 不能只在脑子里比较，必须写出来让用户看到
4. **交叉分析是核心** — 单家分析只是输入，四家交叉对比才能得出有意义的结论
5. **行动建议要具体** — 不是"建议参考 Mursion"，而是"建议参考 Mursion 的 Character Bible 机制，具体做法是 XXX"
6. **搜索不到不丢人** — 如果某家在某域确实没有公开资料，标注"未找到相关公开信息"，不要编造

## 对标范围判断

对标不是每个小改动都要做。以下情况可以跳过：
- 纯 bug 修复（不改功能逻辑）
- UI 微调（不改变信息架构或交互流程）
- 文案修改（不影响评分或行为检测）

以下情况必须对标：
- 新增场景/角色/面谈类型
- 修改评分算法或反馈逻辑
- 新增对话引擎功能（检测/轻声提醒/纠偏）
- 新增页面或重大 UI 重构
- 技术架构变更
- 引入新的 AI 能力（如语音、情绪识别）
